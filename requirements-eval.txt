# requirements-eval.txt — opt-in extras for the repo-screening
# deepeval eval primitive (2026-05-11).
#
# Why a separate file? Same rationale as ``requirements-cloud.txt``
# for SkyPilot: deepeval drags in a heavy dep tree (openai, posthog,
# pyfiglet, sentry-sdk, pytest-xdist, aiohttp, ...) for a primitive
# that ships DORMANT and is never invoked inside a run loop. Splitting
# keeps the base install lean and lets operators who want the eval
# primitive run::
#
#     pip install -r requirements-eval.txt
#
# Without this file installed:
# * ``eval_pkg.scoring.is_enabled()`` reports False regardless of config.
# * Every ``score_response()`` call returns a zero-score EvalScore
#   with ``error=True`` and outcome ``disabled``.
# * The orchestrator boots fine; unit tests pass (they mock OllamaModel).
#
# After installing, flip ``eval.enabled=true`` in ``config.json``
# and the ``score_response()`` primitive becomes live against the
# Ollama judge at ``eval.judge_base_url``.
#
# Apache-2.0. First-class Ollama judge support via ``OllamaModel``.
# The ``ollama`` python client is a deepeval optional that has to be
# installed alongside it (deepeval 4.0 raises DeepEvalError on
# OllamaModel construction without it).
deepeval>=4.0,<5
ollama>=0.6,<1
