## Plan deviations approved + validated

Carried forward from Phase B handoff (still relevant):

1. `query_ollama` / `query_ollama_structured` keep their original POSITIONAL `run_id` parameter (no `_run_id` rename). State hook reads via `prefect.runtime.task_run.parameters` (NOT `task_run.parameters`, which is empty in local-mode harness in Prefect 3.6.29).
2. `LlmResponse` dataclass return type for both ollama functions; state hook duck-types `getattr(state.result(), "eval_count", ...)`.
3. `cache_policy=NO_CACHE` lives at `prefect.cache_policies.NO_CACHE` (NOT `prefect.tasks.cache_policies`).
4. Autouse session-scoped `prefect_test_harness` fixture in `tests/conftest.py`.

New in Phase C:

5. **Prefect 3.x `Task.map()` iterates dicts but auto-broadcasts strings.** Only `str`/`bytes`/`io.IOBase` are auto-broadcast (verified at `prefect/utilities/collections.py:155 isiterable`). Dict args (`plan`, `env`) MUST be wrapped in `unmapped()`. `from prefect import flow, task, unmapped` is now in `orchestration/__init__.py`. See `feedback_prefect_map_unmapped.md` in memory.

New in Phase E:

6. **Prefect 3.x flows have NO `.submit()` method** — that's a Task method. The plan's `flow.with_options(name=...).submit(args).wait()` pattern is wrong for 3.x and would `AttributeError` at runtime. Correct subflow invocation is direct call: `child_flow.with_options(name=...)(args)`. Verified empirically against installed Prefect 3.6.29. `combo_id` referenced in the plan doesn't exist; use `run_id[:8]` for the subflow name. See `feedback_prefect_subflow_invocation.md` in memory.
7. **Hook-name asymmetry is intentional.** Decorator kwarg is `on_cancellation` (Prefect API). Function in `prefect_io.state_hooks` is `on_cancelled` (past-tense). Both correct: `on_cancellation=[on_cancelled]`.

## Execution discipline used (carry forward)

- **Subagent-driven development** (skill: `superpowers:subagent-driven-development`): per task, dispatch implementer → combined sonnet spec+quality reviewer. Combined review acceptable on mechanical commits to save a round-trip.
- **Model selection (validated empirically)**:
  - **Sonnet** for tasks involving prod-code judgment, refactors, multi-file integration, signature changes, plan deviations, or anywhere the implementer might over-think.
  - **Haiku** ONLY for genuinely-mechanical work — single decorator add + single call-site change with NO semantic shift. Use HARD scope guardrails ("DO NOT MODIFY <files>", scope guardrail line counts, explicit DO NOT lists) — haiku has over-implemented in this project at least once (B2 added a side-channel global dict that had to be reverted).
- **Conventional Commits** (`feat:`, `fix:`, `refactor:`, `test:`, `chore:`, `docs:`).
- **Push at every phase boundary** for a checkpoint, then pause for user sign-off.
