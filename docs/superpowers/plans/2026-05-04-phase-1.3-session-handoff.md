## Plan deviations (all approved by Louis, validated by tests)

1. **Skipped the `_run_id` keyword-arg rename** that the plan called for in `query_ollama` / `query_ollama_structured`. Both functions take `run_id` as the LAST positional arg today; Prefect's runtime context captures positional args by name, so the state hook reads `params.get("run_id")` (no underscore) and it works. Saves churn at 11 call sites in `orchestration/__init__.py` and 1 in `tools/__init__.py`.

## Critical Prefect 3.6.29 finding (will affect every future hook)

**`task_run.parameters` (the attribute on the TaskRun schema object passed to state hooks) is empty/None in local-mode `prefect_test_harness` execution.** Use `prefect.runtime.task_run.parameters` (the RuntimeContext accessor) instead. Verified against Prefect source at `prefect/task_engine.py:772` — `setup_run_context()` wraps hook invocation in `SyncTaskRunEngine`, so the runtime accessor is populated when `on_completion` / `on_failure` fire.

The current fallback chain in `prefect_io/state_hooks.py` is:

```python
import prefect.runtime.task_run as _prefect_task_run
...
params = (
    _prefect_task_run.parameters
    or getattr(task_run, "parameters", None)
    or {}
)
```

The `getattr` fallback is needed because `tests/test_state_hooks.py` injects a MagicMock with `.parameters` set directly. Don't remove it.

Also: `cache_policy=NO_CACHE` lives at `prefect.cache_policies.NO_CACHE` (NOT `prefect.tasks.cache_policies`).
